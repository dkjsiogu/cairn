# 30 · 按区块存快照，按区块回档

> 0.45。科技包里出事往往只坏一小片：机器炸了、区块被 Mod 写坏、实体卡死。整个世界退回去会把别处的进度一起丢掉，所以快照细到区块，回档也只换选中的那几块。

## 1. 存法

| 以前 | 现在 |
|---|---|
| 所有文件按内容分块（64 KiB–4 MiB） | 区域文件（`region/`、`entities/`、`poi/` 下的 `r.X.Z.mca`）按区块拆开，一个区块一个对象；其他文件照旧分块 |
| 每个块一个文件（`repo/objects/ab/cdef…`） | 对象写进包：每次快照最多新增一个 `repo/packs/<id>.pack` 和 `.idx` |
| 每次都读完整个世界 | 大小和修改时间都没变的文件直接沿用上一份的记录，不再读 |
| 不记空文件夹 | 记下空文件夹，整份恢复时建回来 |

区域文件在清单里只记一张**区块表**（也是一个对象）：每个区块的序号、保存时间和数据的哈希，每行 26 字节。区块数据原样存（压缩方式那 1 字节加压缩后的内容），不解压、不重新压缩，所以没动过的区块两份快照共用同一个对象。格式读不懂的区域文件（被截断、位置越界）按普通文件存。

旧版本的快照照常能读、能整份恢复、能回档区块：散放的对象从 `objects/` 读，整文件存的区域文件拼回来再拆。

实测一个 453 MB 的模组服务器世界（839 个区域文件、4 万多个区块）：

| | |
|---|---|
| 第一份快照 | 0.44 秒，仓库 331 MB，3 个文件（原来是 48 580 个散文件） |
| 什么都没变时再快照 | 9 毫秒，不新增对象 |
| 读区块地图 | 14 毫秒（只读每个区域文件的 8 KiB 文件头） |
| 回档 5×5 区块 | 32 毫秒，含回档前的自动快照 |
| 整份恢复 | 0.36 秒，839 个区域文件和原来逐区块一致 |

（tmpfs 上测的，机械硬盘会慢一些。）

## 2. 回档区块

快照行上的「回档区块」打开地图：

- 按维度看，主世界、下界、末地是按钮，模组维度放进下拉。
- 每个区块按和快照比的结果上色：**改过**（之后又保存过）、**新生成**（快照之后才有）、**已删除**、**没变**。比的是区域文件头里的保存时间，所以很快。地图一打开先看改动最集中的地方。
- 拖动框选，右键拖动平移，滚轮缩放；也可以输入方块坐标跳过去。
- 选区里写明多少个区块改过、多少个是之后新生成的。

回档时：

1. 选区里每个区块的地形、实体、兴趣点三样一起换回快照里的样子；内容和快照一样的不动。
2. 快照里没有的区块（之后新生成的）删掉，下次进游戏按种子重新生成。
3. 放不进区域文件的大区块（`c.X.Z.mcc`）一起换。
4. 有任何不同才动手：先自动快照一份当前世界，备注「回档区块前」，回档错了从它再回档回来。
5. 区域文件读不懂就整个停下，一个文件都不改。
6. 游戏开着这个版本时不让回档；Windows 上还会看 `session.lock` 有没有被占着。

## 3. 清理

「清理旧快照」和自动备份结束时的清理以前只看 `saves/` 里现在还有的世界：删掉一个世界之后再清理，它的快照引用的对象全被当成没用的删掉，那些快照就再也恢复不了。现在按快照仓库里的目录走，删掉的世界的快照照样保留、照样算引用。

- 有读不懂的清单时只删超出份数的旧快照，不回收对象。
- 包里的对象全没用就删掉整个包；没用的占到四分之一以上时把有用的挪进新包，再删旧包。
- 写快照、清理、回档区块互相等待，不会删掉还没写进清单的新对象。
